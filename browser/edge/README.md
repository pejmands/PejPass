# PejPass for Microsoft Edge

The extension reads the active HTTP(S) tab hostname and requests matching account metadata from the local PejPass desktop app. Passwords and a current TOTP code are retrieved only after the user explicitly selects **Fill login** for a matching account. It can launch the desktop app and submit a master password for local vault verification. It can also generate passwords locally in the popup using the browser's cryptographic random number generator.

## Requirements

- Microsoft Edge
- .NET 10 SDK
- A local checkout of this repository

## Load the extension

1. Open `edge://extensions` in Edge.
2. Enable **Developer mode**.
3. Select **Load unpacked**.
4. Choose the `browser/edge` directory.
5. Copy the extension ID shown on the extension card.

## Build and register the local host

From the repository root, run PowerShell with the extension ID copied above:

```powershell
powershell -ExecutionPolicy Bypass -File .\browser\edge\install-dev-host.ps1 -ExtensionId YOUR_32_CHARACTER_EXTENSION_ID
```

The script builds `src/PejPass.BrowserHost`, writes a host manifest under its Release output directory, and registers that manifest for the current Windows user in Edge. It does not require administrator privileges. Restart Edge after registration if it was already running.

To remove the registration later:

```powershell
powershell -ExecutionPolicy Bypass -File .\browser\edge\uninstall-dev-host.ps1
```

## Manual checks

- The password generator supports lengths from 8 to 64 characters, configurable lowercase, uppercase, numeric, and symbol sets, and ensures at least one character from each selected set. It uses `crypto.getRandomValues`, rejection sampling to avoid modulo bias, and a cryptographic shuffle. Generated passwords are not saved automatically.
- The popup displays the active hostname on ordinary HTTP(S) pages; restricted browser pages show an unavailable message.
- The popup reports the live desktop connection and vault lock state. When the popup can verify the vault state, it updates the Edge toolbar icon to show the unlocked or locked vault. The toolbar uses the same locked and unlocked ICO assets as the desktop app, with a locked icon as the default before the first successful status check. When unlocked, select **Lock vault** to lock the desktop vault immediately; the popup clears account metadata, save-form values, and its generated password. If the desktop app is not running, select **Launch PejPass**; the native host launches the Release build from the repository checkout.
- When the vault is locked, the popup accepts the master password and forwards it through Native Messaging and the current-user-only named pipe to the desktop app. The desktop app verifies it using its existing vault-opening flow. The extension clears the password field after each attempt and does not store the password. This requires an existing vault selected in PejPass and a Release build created by `install-dev-host.ps1`.
- When unlocked, the popup lists entries whose saved URL host is the active site host or a parent domain of it. Matching is case-insensitive and does not match lookalike sibling domains.
- Only entry ID, title, username, and saved URL are sent for lookup. Passwords, TOTP secrets, notes, custom fields, and key material are excluded from lookup responses. A current TOTP code is generated by the desktop app only during an explicit fill request; the raw TOTP secret is never sent to the extension.
- When locked, the extension shows an unlock message and receives no account metadata.
- Selecting **Fill login** requests the chosen credential from the desktop app, revalidates the account ID and active hostname, and checks the main document plus accessible same-site frames. If the page is on a username-first step, it fills a likely visible username field and asks you to continue on the site; select **Fill login** again after the password step appears. When a password field is present, it fills the password and a likely username field in the same form when available. If a visible one-time-code field is present, it also fills a current TOTP code when the selected entry has a valid TOTP secret. Cross-origin frames are intentionally not filled.
- Filling is always user-triggered. The extension does not submit the form. Review the filled fields and submit the login yourself.
- After a login is successfully saved or updated, the extension clears and hides the temporary save form, including its password field.
- The extension checks the page hostname again immediately before filling and does not fill if the page changed.
- The host accepts version-1 `ping`, `launchApp`, `unlockVault`, `lockVault`, `getVaultStatus`, `getCredentials`, `fillCredential`, and `saveCredential` requests. Requests are validated by both the host and desktop endpoint.
- Successful credential fill and save operations reset the desktop AutoLock timer. Passive status checks and credential metadata lookups do not reset it.
- The desktop endpoint uses a current-user-only named pipe. Credential lookup is limited to 25 results.
- The extension requests `activeTab`, `clipboardWrite`, `nativeMessaging`, and `scripting`; it does not run a persistent content script or read page contents in the background.

## Current scope

Autofill supports visible username-like and password inputs in the main page document and accessible same-site frames. For multi-step login pages, fill the username first, continue on the website, then select **Fill login** again to fill the password or a detected one-time-code field. TOTP autofill requires a valid TOTP secret stored with the selected entry. It does not automatically submit forms or handle login fields inside cross-origin frames.
